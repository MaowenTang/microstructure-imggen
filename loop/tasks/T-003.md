## Goal (stop condition)

A yes/no answer, with curves, to: "can the current U-Net + spatial-latent
architecture represent patch-scale ripple geometry at all, when distribution
learning is removed?" Passing justifies spending T-004's 30 GPU-hours on
longer training; failing redirects effort to architecture before any long
training run.

## Background

The paper observes that local texture is learned but long-range ripple
geometry is weak. Two rival explanations produce this same signature:
(a) the architecture cannot represent global arcs (capacity/attention
placement), (b) the distribution over global layouts is underdetermined by
~8 source images. Overfitting a single source image removes (b): if the model
still cannot match that one image's own ripple statistics, the bottleneck is
(a). **Dispatch gate: T-002 ACCEPTED and `task/T-002` merged into main**
(this task imports T-002's `src/morph_eval.py`; cut your branch from main
only after that merge — verify with
`git merge-base --is-ancestor task/T-002 main` before starting, and stop
with a report if it fails). Paths from `results/T-001/repo_map.md`; architecture
and hyperparameters must be IDENTICAL to the paper's base config (U-Net 128/192/256/320,
attention at two middle levels, 1000-step squared-cosine schedule, AdamW
1e-4, batch 4, grad-accum 2, EMA 0.999) except the dataset restriction.

### Verdict rule (write the answer, not just data)

PASS if at any checkpoint: ripple score ≥ 0.90 × the image's own mean AND
Sobel edge mean ≥ 0.90 × the image's own mean. Report NN ratio at that
checkpoint (memorization is EXPECTED and acceptable here — this task tests
representational capacity, not generalization; say so explicitly).
FAIL otherwise → recommend ESCALATE, with the descriptor that refused to
converge named.
